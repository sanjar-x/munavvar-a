# Исследование: Дашборд управления заказами и доставкой для MunavvarA (HOD)

**Дата исследования:** 01.04.2026
**Область:** Orders / Delivery Management — раздел админ-панели
**Целевая аудитория дашборда:** Администратор (диспетчер), Кладовщик, Кассир, Бухгалтер

---

## 1. Резюме (Executive Summary)

Данное исследование охватывает лучшие мировые практики построения дашбордов управления заказами и доставкой для бизнеса по доставке бутилированной воды. Исследованы решения лидеров рынка (Onfleet, Track-POD, Rekart, Water Delivery Solutions, Trakop, Shopify, Odoo, iiko, Яндекс.Доставка, Route4Me, DispatchTrack), а также общие принципы UX/UI дизайна логистических дашбордов.

### Ключевые выводы:

1. **Двухуровневая архитектура дашборда** — оперативный слой (живая карта + канбан заказов + статусы курьеров) и аналитический слой (тренды, KPI, воронки, сравнения).

2. **Канбан-доска статусов заказов** — самый популярный паттерн в индустрии доставки. Колонки соответствуют статусам FSM (Новый → Назначен → В пути → Прибыл → Доставлен / Отменён). Каждая карточка содержит краткую информацию о заказе.

3. **Карта в реальном времени** — обязательный элемент диспетчерского интерфейса. Отображает позиции курьеров, точки доставки, маршруты, зоны обслуживания.

4. **Учёт возвратной тары** — критически важная специфика водного бизнеса. Ведущие платформы (Rekart, Trakop, Water Delivery Solutions) имеют специализированные виджеты для отслеживания циркуляции бутылей, баланса тары у клиентов, просроченных возвратов.

5. **Аналитика разделяется на B2B и B2C** — разные метрики, паттерны заказов, способы оплаты. B2B фокусируется на частоте заказов, объёмах, задолженности по договору. B2C — на конверсии, среднем чеке, частоте повторных заказов.

6. **Частичная доставка** — требует отдельной визуализации и метрик (процент полных доставок vs частичных, причины недопоставок).

## 2. Рекомендуемые KPI для управления заказами MunavvarA

### 2.1 Операционные KPI (ежедневные)

| KPI                            | Описание                          | Формула                                                         | Целевое значение    |
| ------------------------------ | --------------------------------- | --------------------------------------------------------------- | ------------------- |
| **Заказы сегодня**             | Общее число заказов за день       | COUNT(orders WHERE date=today)                                  | Отслеживание тренда |
| **Заказы по статусам**         | Распределение по FSM-статусам     | COUNT GROUP BY status                                           | Минимум в "Новый"   |
| **Среднее время обработки**    | От создания до назначения курьера | AVG(assigned_at - created_at)                                   | < 30 мин            |
| **Среднее время доставки**     | От назначения до завершения       | AVG(delivered_at - assigned_at)                                 | < 2 часов           |
| **Процент доставки в срок**    | Доля доставок в обещанное окно    | delivered_on_time / total_delivered \* 100                      | > 95%               |
| **Процент отмен**              | Доля отменённых заказов           | cancelled / total \* 100                                        | < 5%                |
| **Процент частичных доставок** | Доля доставок с недопоставкой     | partial_deliveries / total_delivered \* 100                     | < 10%               |
| **Загрузка курьеров**          | Заказов на курьера сегодня        | orders_assigned / active_couriers                               | 15-25               |
| **Незакрытые заказы**          | Заказы старше 24ч без доставки    | COUNT(orders WHERE age > 24h AND status != delivered/cancelled) | 0                   |

### 2.2 Аналитические KPI (еженедельные/месячные)

| KPI                                 | Описание                                     | Формула                                    |
| ----------------------------------- | -------------------------------------------- | ------------------------------------------ |
| **Средний чек (AOV)**               | Средняя сумма заказа                         | SUM(order_total) / COUNT(orders)           |
| **Объём заказов (тренд)**           | Динамика количества заказов по дням/неделям  | COUNT(orders) GROUP BY period              |
| **Выручка от заказов**              | Общая выручка за период                      | SUM(order_total) WHERE status=delivered    |
| **Процент выполнения (Fill Rate)**  | Доля успешно доставленных заказов            | delivered / (delivered + cancelled) \* 100 |
| **Коэффициент повторных заказов**   | Доля клиентов с повторным заказом за 30 дней | repeat_customers / total_customers \* 100  |
| **Среднее кол-во бутылей на заказ** | Средний размер заказа в штуках               | SUM(items_qty) / COUNT(orders)             |
| **Соотношение B2B/B2C**             | Доля заказов от каждого сегмента             | COUNT GROUP BY client_type                 |
| **Доставка vs Самовывоз**           | Соотношение каналов выполнения               | COUNT GROUP BY order_type                  |
| **Распределение способов оплаты**   | Наличные / Карта / Договор                   | COUNT GROUP BY payment_method              |
| **Коэффициент возврата тары**       | Процент возвращённых бутылей от выданных     | returned_bottles / issued_bottles \* 100   |
| **Дефицит тары при заказе**         | Процент заказов с капитализацией             | orders_with_capitalization / total \* 100  |

### 2.3 KPI курьеров

| KPI                               | Описание                        | Формула                                            |
| --------------------------------- | ------------------------------- | -------------------------------------------------- |
| **Доставок в день**               | Количество завершённых доставок | COUNT(delivered) WHERE courier=X AND date=today    |
| **Средняя скорость доставки**     | Время от выезда до завершения   | AVG(delivered_at - in_transit_at)                  |
| **Процент on-time**               | Доля своевременных доставок     | on_time / total \* 100                             |
| **Процент отмен по вине курьера** | Доля отмен после назначения     | cancelled_after_assign / assigned \* 100           |
| **Собрано наличных**              | Наличные на кассе курьера       | SUM(cash_collected) WHERE courier=X AND date=today |
| **Несданные наличные**            | Баланс кассы курьера            | courier_cash_balance                               |
| **Остаток товара в машине**       | Текущий груз курьера            | SUM(inventory) WHERE courier_vehicle=X             |

## 3. Рекомендации по компоновке дашборда (Layout)

### 3.1 Концепция: три уровня представления

Опираясь на лучшие практики Onfleet, Track-POD, DispatchTrack и Rekart, рекомендуется трёхуровневая структура:

```
┌─────────────────────────────────────────────────────────────┐
│  УРОВЕНЬ 1: Оперативный центр (Dispatch Center)            │
│  Целевой пользователь: Администратор-диспетчер              │
│  Частота использования: Весь рабочий день, непрерывно       │
│  Назначение: Управление заказами в реальном времени         │
├─────────────────────────────────────────────────────────────┤
│  УРОВЕНЬ 2: Аналитический дашборд (Order Analytics)        │
│  Целевой пользователь: Администратор, Руководитель          │
│  Частота: Ежедневно утром, в конце дня, еженедельно        │
│  Назначение: Тренды, сравнения, прогнозы, эффективность    │
├─────────────────────────────────────────────────────────────┤
│  УРОВЕНЬ 3: Дашборд курьеров (Courier Dashboard)           │
│  Целевой пользователь: Администратор, Бухгалтер            │
│  Частота: В течение дня и при закрытии смен                │
│  Назначение: Загрузка, статусы, наличные, тара             │
└─────────────────────────────────────────────────────────────┘
```

**Ключевые элементы оперативного центра:**

1. **Счётчики статусов (Status Counters)** — цветные бейджи с числом заказов в каждом статусе. По клику — фильтрация. Цвета:
   - Новый — серый/синий
   - Назначен — фиолетовый
   - В пути — оранжевый
   - Прибыл — жёлтый
   - Доставлен — зелёный
   - Отменён — красный
   - Самовывоз завершён — бирюзовый

2. **Канбан-доска заказов** — колонки = статусы FSM. Карточки перетаскиваются между колонками (drag-and-drop для назначения). На каждой карточке:
   - Номер заказа
   - Имя клиента (+ бейдж B2B/B2C)
   - Краткий состав (кол-во бутылей)
   - Сумма
   - Способ оплаты (иконка)
   - Адрес
   - Время создания
   - Курьер (если назначен)
   - Индикатор частичной доставки (если применимо)

3. **Карта реального времени** — альтернативный вид. Маркеры заказов + иконки курьеров. При наведении — мини-карточка заказа. Маршруты линиями.

4. **Табличный вид** — для массовых операций. Сортировка по любому полю, групповое назначение курьеров, экспорт.

5. **Панель курьеров** — внизу или в боковой панели. Для каждого курьера: имя, количество заказов, текущий статус (свободен / в пути / на месте), баланс наличных.

### 4.1 Рекомендуемые типы диаграмм

## 5. Примеры из реальных решений

### 5.1 Onfleet (лидер рынка Last Mile Delivery)

**Ключевые элементы дашборда:**

- **Map + Sidebar** — два основных компонента. Карта занимает 70% экрана, боковая панель — 30%.
- **Неназначенные задачи** — отображаются серыми маркерами на карте и в верхней секции сайдбара.
- **Назначенные задачи** — фиолетовые маркеры, группируются под именем курьера.
- **Drag-and-drop** — перетаскивание задач на курьера или между позициями маршрута.
- **Auto-assignment** — AI-распределение заказов по ближайшим курьерам.
- **Table View** — альтернативный табличный вид с сортировкой, фильтрами и массовыми действиями.
- **Task Status Colors** — серый (неназначен), фиолетовый (назначен), жёлтый (в пути), зелёный (завершён), красный (неудачно).
- **Command Center** — централизованный хаб для мониторинга всех операций.

**Применимость для MunavvarA:** Высокая. Паттерн Map + Sidebar с канбан-колонками — идеальная основа для диспетчерского интерфейса.

### 5.2 Rekart / Trakop / Water Delivery Solutions (специализированные решения для воды)

**Специфические элементы:**

- **Bottle tracking dashboard** — отслеживание циркуляции бутылей: выдано, возвращено, в обороте, просроченные возвраты.
- **Customer bottle balance** — баланс тары по каждому клиенту с историей.
- **Deposit management** — учёт залогов за тару, кредиты, возвраты.
- **Subscription management** — управление периодическими заказами (в случае MunavvarA — потенциальная будущая функция).
- **Failed delivery tracking** — учёт неудавшихся доставок с причинами.
- **Multi-hub support** — работа с несколькими складами.
- **Driver cash reconciliation** — сверка наличных курьера с ожидаемой суммой.

**Применимость для MunavvarA:** Очень высокая. Учёт тары, баланс бутылей, кассовая сверка — прямое соответствие бизнес-модели.

### 5.3 Shopify / Metorik (e-commerce аналитика)

**Ключевые паттерны аналитики:**

- **KPI-карточки с трендами** — число + процент изменения + мини-спарклайн.
- **Heatmap Weekly Sales Patterns** — тепловая карта по дням и часам (Shopify недавно добавил этот виджет).
- **RFM-анализ** — сегментация клиентов по Recency-Frequency-Monetary (автоматические оценки 1-5 по каждому параметру).
- **Cohort analysis** — когортный анализ повторных покупок.
- **Product performance** — рейтинг товаров по объёму продаж.
- **Multi-channel comparison** — сравнение каналов продаж.

**Применимость для MunavvarA:** Средняя. Аналитические паттерны (KPI-карточки, тренды, heatmap) применимы. RFM-анализ полезен для B2B-клиентов.

### 5.4 iiko + Яндекс.Доставка (российский рынок HoReCa)

**Ключевые элементы:**

- **Интеграция источников заказов** — заказы из разных каналов (приложение, сайт, телефон) объединяются в один поток.
- **Статусы с цветовой индикацией** — визуально различаются этапы обработки.
- **Автоматическое назначение курьера** — на основе зоны доставки и загрузки.
- **Онлайн-отслеживание курьера** — карта с положением курьера.
- **Настройка временных слотов** — интервалы доставки.

**Применимость для MunavvarA:** Средняя. Паттерн работы с источниками заказов и временными слотами применим.

### 5.5 Route4Me (оптимизация маршрутов)

**Аналитический дашборд:**

- **Route analytics** — анализ маршрутов: запланированное vs фактическое время, отклонения.
- **Driver analytics** — производительность водителей: скорость, простои, время на точке.
- **Geocoding analytics** — точность геокодирования адресов.
- **Custom reporting** — настраиваемые отчёты с экспортом.

**Применимость для MunavvarA:** Низкая на данном этапе (MVP), но полезна при масштабировании.

## 6. Специфические рекомендации для MunavvarA

### 6.1 Визуализация FSM заказов (конечный автомат)

Система MunavvarA имеет два типа FSM:

**FSM доставки:**

```
НОВЫЙ → НАЗНАЧЕН → В ПУТИ → ПРИБЫЛ → ДОСТАВЛЕН
  |         |          |         |
  └─────────┴──────────┴─────────┴──→ ОТМЕНЁН
```

**FSM самовывоза:**

```
НОВЫЙ → САМОВЫВОЗ ЗАВЕРШЁН
  |
  └──→ ОТМЕНЁН
```

**Рекомендации по визуализации:**

1. **Stepper / Progress Bar** на карточке заказа — горизонтальная полоса с шагами. Текущий шаг подсвечен. Показывает, на каком этапе находится заказ.

2. **Воронка конверсии статусов (Funnel)** — аналитический виджет, показывающий сколько заказов «дошло» до каждого этапа. Помогает выявить, на каком этапе теряются заказы.

3. **Sankey-диаграмма переходов** — для углублённого анализа. Показывает потоки: например, 85% заказов из «Новый» ушли в «Назначен», 15% — в «Отменён». Из «Назначен» 95% ушли в «В пути», 5% — в «Отменён».

4. **Среднее время на каждом этапе** — Bar chart с временами: сколько в среднем заказ «висит» в статусе «Новый» (ожидание назначения), сколько в «Назначен» (ожидание выезда) и т.д.

### 6.2 Доставка vs Самовывоз

Это два принципиально разных потока, и дашборд должен это отражать:

**Виджет сравнения каналов:**

- Stacked Bar Chart по дням: голубой = доставка, бирюзовый = самовывоз
- KPI-карточки: «Заказов на доставку: 234 (72%)» | «Самовывоз: 91 (28%)»
- Средний чек по каналам (часто самовывоз = меньший чек)
- Распределение по времени суток для каждого канала

**Фильтрация:**

- Глобальный фильтр «Тип заказа: [Все] [Доставка] [Самовывоз]» на всех уровнях дашборда.
- При выборе «Самовывоз» — скрываются виджеты курьеров и карта.

### 6.3 Назначение курьеров (Dispatch)

**Рекомендуемый workflow:**

1. **Quick Assign** — выпадающий список курьеров на карточке заказа. Рядом с каждым курьером: (имя, текущая загрузка, ближайший адрес).

2. **Batch Assign** — выбрать несколько заказов → «Назначить курьера» → выбрать из списка.

3. **Smart Suggest** — система подсказывает лучшего курьера на основе:
   - Текущей загрузки (кол-во заказов)
   - Наличия товара в машине (хватает ли на этот заказ?)
   - Географической близости (если есть геоданные)

4. **Drag-and-Drop на канбане** — перетащить карточку из «Новый» в столбец курьера.

**Панель курьеров для назначения:**

```
┌─────────────────────────────────────────┐
│ Курьеры на смене        [+ Загрузить]   │
│                                         │
│ 🟢 Алишер (01A 777BC)                  │
│    Заказов: 5/12  |  Груз: 45 бут.      │
│    Наличные: 320K |  Зона: Юнусабад     │
│    [Назначить выбранные]                │
│                                         │
│ 🟢 Бахтиёр (01B 123DE)                 │
│    Заказов: 8/10  |  Груз: 12 бут.      │
│    Наличные: 540K |  Зона: Мирзо-Улуг.  │
│    [Назначить выбранные]                │
│                                         │
│ 🟡 Достон (01C 456FG)                  │
│    Заказов: 10/10 |  Груз: 3 бут.       │
│    ⚠️ Максимальная загрузка            │
│                                         │
│ ⚪ Елдор — Нет активного транспорта    │
└─────────────────────────────────────────┘
```

### 6.4 Частичная доставка

Частичная доставка — уникальная особенность MunavvarA. Рекомендации:

**На карточке заказа:**

- Если доставка частичная — визуальный индикатор (жёлтый бейдж «Частично»)
- Заказано: 10 бутылей → Доставлено: 7 бутылей (70%)
- Пересчитанная сумма: 140,000 → 98,000 сум

**Аналитический виджет:**

- **Процент частичных доставок** — KPI-карточка с трендом.
- **Причины частичных доставок** — Pie Chart: «Нехватка товара у курьера» / «Клиент отказался от части» / «Другое».
- **Средний процент недопоставки** — на сколько % в среднем недопоставляется заказ.
- **Стоимость недопоставок** — потерянная выручка из-за частичных доставок.

### 6.5 Учёт возвратной тары (Tara Exchange)

Это критическая бизнес-функция MunavvarA. Рекомендуемые виджеты:

**Оперативные:**

- **Баланс тары по курьерам** — сколько пустых бутылей собрал каждый курьер за сегодня.
- **Тара к возврату** — заказы, где ожидается обмен тары (число бутылей к сбору).

**Аналитические:**

- **Коэффициент возврата тары** — Gauge: процент возвращённых бутылей от выданных за период.
- **Тара в обороте** — общее количество бутылей у всех клиентов.
- **Клиенты с наибольшим балансом тары** — Top-10 (горизонтальный бар).
- **Заказы с капитализацией тары** — процент заказов, где потребовалась автоматическая капитализация (индикатор проблем с учётом).

### 6.7 Аналитика B2B vs B2C

Для MunavvarA критически важно разделять аналитику по сегментам, так как паттерны заказов сильно отличаются:

**B2B (корпоративные клиенты):**

- Большие объёмы (10-50 бутылей за заказ)
- Регулярная периодичность (еженедельно)
- Оплата по договору (отсрочка → задолженность)
- Фиксированные адреса
- Более высокий AOV, но ниже маржа
- Ключевые метрики: частота заказов, общий объём, задолженность, LTV

**B2C (розничные клиенты):**

- Малые объёмы (1-5 бутылей)
- Нерегулярная периодичность
- Оплата наличными или картой
- Может быть несколько адресов
- Ключевые метрики: конверсия, повторные заказы, средний чек, retention

**Рекомендуемый виджет:**

- Toggle-переключатель «B2B / B2C / Все» на аналитическом дашборде
- Отдельные KPI-карточки для каждого сегмента
- Comparative Bar Chart: объём заказов B2B vs B2C по неделям

```
  → { total, by_status: {new: N, assigned: N, ...}, by_type: {delivery: N, pickup: N} }

GET /api/v1/backoffice/dashboard/orders/trends?period=week&group_by=day
  → [{ date, total, delivery, pickup, b2b, b2c, revenue }]

GET /api/v1/backoffice/dashboard/orders/heatmap?period=month
  → [{ day_of_week, hour, count }]

GET /api/v1/backoffice/dashboard/orders/funnel?period=month
  → { new: N, assigned: N, in_transit: N, arrived: N, delivered: N, cancelled: N }

GET /api/v1/backoffice/dashboard/orders/payment-breakdown?period=month
  → { cash: {count, amount}, card: {count, amount}, contract: {count, amount} }

GET /api/v1/backoffice/dashboard/couriers/summary
  → [{ courier_id, name, vehicle, orders_count, orders_delivered, cash_balance, cargo }]

GET /api/v1/backoffice/dashboard/couriers/performance?period=month
  → [{ courier_id, name, deliveries, avg_time, on_time_rate, partial_rate }]

GET /api/v1/backoffice/dashboard/tara/summary?period=month
  → { issued, returned, return_rate, capitalized, top_debtors: [...] }

GET /api/v1/backoffice/dashboard/orders/partial-deliveries?period=month
  → { total_partial, partial_rate, avg_underfulfillment_pct, lost_revenue }

GET /api/v1/backoffice/dashboard/orders/top-clients?period=month&limit=10
  → [{ client_id, name, type, orders_count, total_amount }]
```

### 7.3 Кеширование и производительность

- **Summary/Counters** — обновление каждые 30 секунд (polling) или WebSocket.
- **Analytics (trends, heatmap, funnel)** — кеш 5 минут, инвалидация при новом заказе не нужна (допустима задержка).
- **Courier positions** — если реализовать карту, WebSocket обязателен для позиций.
- **RTK Query** — используйте `pollingInterval` для автоматического обновления.

### 7.4 Адаптивность и мобильный доступ

- Оперативный центр (канбан + карта) — **только десктоп** (минимум 1280px).
- Аналитический дашборд — **десктоп + планшет** (минимум 768px). KPI-карточки перестраиваются в 2 колонки.
- Список курьеров — **адаптивный до мобильного**.

## 8. Приоритизация реализации

### Фаза 1: MVP дашборда (2-3 недели)

1. **Счётчики статусов** — цветные карточки с числом заказов в каждом статусе

5. **Панель курьеров** — список активных курьеров с загрузкой и балансом

### Фаза 2: Оперативное управление (2-3 недели)

1. **Канбан-доска** — колонки по статусам с drag-and-drop
2. **Batch operations** — групповое назначение, групповая отмена
3. **Фильтр по типу** — доставка / самовывоз / все
4. **Быстрые действия** — кнопки смены статуса прямо из списка

1. **KPI-карточки** — 8 основных метрик с трендами

3. **Частичные доставки** — метрики и причины
4. **Топ-клиенты** — рейтинг по объёмам
5. **Экспорт отчётов** — PDF/Excel

## 10. Итоговые рекомендации

### Что строить в первую очередь:

1. **Оперативный список заказов** с цветными счётчиками статусов и быстрым назначением курьеров — это «хлеб» диспетчера, используется весь рабочий день.

2. **Канбан-доску** с drag-and-drop — второй приоритет после списка. Визуальное представление потока заказов значительно ускоряет работу диспетчера.

3. **Панель курьеров** с текущей загрузкой, балансом наличных и остатком товара — критично для принятия решений о назначении.

4. **KPI-карточки** с 8 ключевыми метриками — для ежедневного контроля здоровья операций.

5. **Тренд заказов + Тепловая карта пиковых часов** — для планирования ресурсов.

### Что НЕ строить на этапе MVP:

- Карту реального времени (требует инфраструктуры GPS-трекинга)
- Оптимизацию маршрутов (сложный алгоритм, можно обойтись ручным назначением)
- Предиктивную аналитику (нужна история данных минимум за 3-6 месяцев)
- RFM-анализ (полезен, но не критичен на старте)

### Архитектурный принцип:

Все аналитические данные для дашборда должны вычисляться через **отдельные read-only query-эндпоинты** (CQRS-паттерн), а не через основные CRUD-сервисы. Это позволит:

- Оптимизировать SQL-запросы для агрегатов
- Не нагружать основные транзакционные таблицы
- Кешировать результаты независимо
- Масштабировать чтение отдельно от записи
