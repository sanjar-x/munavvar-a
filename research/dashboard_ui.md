## 1. Резюме для руководства

### Контекст проекта

MunavvarA (HOD) — B2B/B2C-платформа для управления доставкой бутилированной воды в Узбекистане. Система охватывает полный цикл операций: от приёма заказа до доставки курьером, учёта каждой бутыли, финансовой отчётности с двойной бухгалтерией. Работает с узбекским сумом (UZS), форматом телефонов +998.

### Ключевые требования к UI

Админ-панель MunavvarA должна обслуживать **7 ролей** (администратор, бухгалтер, кладовщик, кассир, курьер, клиент B2C, клиент B2B), каждая с различным набором разделов. Интерфейс должен поддерживать:

- **Финансовый дашборд** — выручка, касса, ожидающие платежи, долги клиентов, наличные у курьеров
- **Управление заказами** — жизненный цикл из 6 статусов, частичная доставка, самовывоз
- **Складскую логистику** — 9 типов перемещений товара, контроль остатков, инвентаризация
- **Учёт тары** — правило обмена 1:1, капитализация, баланс бутылей у клиентов
- **Закрытие смен курьеров** — атомарная 4-шаговая процедура
- **Подтверждение карточных платежей** — ожидающие транзакции для бухгалтера

### Главная рекомендация

**Ant Design v6 + ProComponents** в качестве основной UI-библиотеки, **Recharts** для графиков, с **тёмным сайдбаром + светлым контентом** как основным макетом. Эта комбинация оптимальна для data-heavy операционного дашборда с учётом:

- Полной совместимости с React 19
- Богатейшего набора бесплатных enterprise-компонентов (Table, Form, Tree, Transfer)
- ProTable/ProForm для быстрой разработки CRUD-интерфейсов
- Существующей экосистемы RTK Query в проекте

## 2. Рекомендуемый UI-фреймворк

### Почему Ant Design v6

Ant Design v6 — **оптимальный выбор** для MunavvarA по совокупности факторов:

**Совместимость с React 19:**

- Ant Design v6 **нативно поддерживает React 19** — удалён весь legacy-код совместимости
- Больше не требуется пакет `@ant-design/v5-patch-for-react-19`
- React Compiler включён в бандлированные выходные файлы для улучшения производительности
- Плавная миграция с v5 без codemod-инструментов

**Enterprise-компоненты без оплаты:**

- 60+ компонентов бесплатно, включая: Table, Form, Tree, Transfer, Cascader, DatePicker, TimePicker, InputNumber, Mentions, Steps, Statistic, Descriptions, Badge, Tag, Timeline
- В отличие от MUI, где Data Grid Pro/Premium платный, у Ant Design всё включено
- ProComponents (ProTable, ProForm, ProLayout, ProCard, ProList, ProDescriptions) — бесплатная надстройка

**Идеальное соответствие бизнес-задачам MunavvarA:**

- Компонент `Table` с серверной пагинацией, сортировкой, фильтрацией — для списков заказов, клиентов, перемещений
- Компонент `Statistic` — для финансового дашборда (выручка, касса, долги)
- Компонент `Steps` — для визуализации жизненного цикла заказа (6 статусов)
- Компонент `Tag` с цветовой кодировкой — для статусов заказов
- Компонент `Descriptions` — для карточек клиентов, заказов, перемещений
- Компонент `Transfer` — для назначения курьеров на заказы
- Компонент `Form` с валидацией — для всех CRUD-операций
- Компонент `Badge` — для ожидающих подтверждения платежей

**Совместимость с текущим стеком:**

- Проект уже использует Redux Toolkit + RTK Query — Ant Design прекрасно работает с любой state-management библиотекой
- React Router v7 — Ant Design ProLayout интегрируется с React Router
- Vite 7 — полная поддержка tree-shaking для Ant Design

### Почему не другие библиотеки

| Библиотека    | Причина отказа                                                                                                                                                                                 |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **MUI**       | Data Grid Pro/Premium платный ($249+/разр./год). Для бесплатного Data Grid нет серверной пагинации. Theming система сложнее (createTheme, sx prop, slots).                                     |
| **Mantine**   | Отличная библиотека, но нет ProComponents-аналога для быстрого CRUD. Нет встроенного Table уровня Ant Design. Потребуется больше custom-кода.                                                  |
| **shadcn/ui** | Нет готовых enterprise-компонентов (Table, Transfer, Steps). Каждый компонент — исходный код в проекте, что увеличивает maintenance. Подходит для продуктовых лендингов, не для admin-панелей. |
| **Chakra UI** | Меньше enterprise-компонентов. Популярность падает в 2025-2026. Не оптимизирован для data-heavy интерфейсов.                                                                                   |

### Установка и настройка

```bash
# Основная библиотека
npm install antd @ant-design/pro-components

# Иконки
npm install @ant-design/icons

# Графики (см. раздел 4)
npm install recharts
```

### ProComponents — ключевое преимущество

Ant Design ProComponents — это набор высокоуровневых компонентов, которые резко ускоряют разработку admin-панелей:

**ProTable:**

- Автоматическая серверная пагинация через `request` API
- Встроенная строка поиска/фильтрации (query form)
- Toolbar с кнопками действий, настройками колонок, полноэкранным режимом
- Inline-редактирование ячеек
- Batch-операции с выделением строк
- Экспорт данных

**ProForm:**

- StepsForm — пошаговые формы (для создания клиента «Единое окно»)
- ModalForm — формы в модальных окнах
- DrawerForm — формы в выдвижных панелях
- QueryFilter — компактные формы фильтрации
- LoginForm — готовая форма входа

**ProLayout:**

- Готовый sidebar с навигацией, поддержкой вложенных пунктов
- Встроенные breadcrumbs
- Header с actions-area
- Адаптивный: автоматическое сворачивание сайдбара на мобильных
- Конфигурация меню через JSON/массив маршрутов

**ProCard:**

- Stat-карточки для KPI (выручка, касса, долги)
- Группировка карточек в сетку
- Checkable-карточки для выбора

**ProDescriptions:**

- Автоматическая генерация описательных блоков (карточка клиента, детали заказа)
- Поддержка inline-редактирования

### Рекомендация: Recharts

**Recharts** — оптимальный выбор для MunavvarA по следующим причинам:

1. **Наибольшее сообщество** — 3.5 млн загрузок/неделю, максимальное количество примеров и решений на StackOverflow
2. **React-нативный API** — каждый элемент графика — React-компонент, что естественно для React-разработчиков
3. **Полная совместимость с React 19** — без хаков и legacy-флагов
4. **Достаточный набор типов** — Line, Bar, Area, Pie, Radar, Scatter, Treemap, Funnel — покрывает все потребности финансового дашборда
5. **Лёгкий бандл** — ~45 KB gzip, не раздувает приложение
6. **ResponsiveContainer** — встроенная адаптивность без дополнительного кода
7. **Хорошая интеграция с Ant Design** — одинаковые цвета через Design Tokens

Для **sparklines** на KPI-карточках можно использовать `<AreaChart>` с минимальной конфигурацией или `@ant-design/charts` для мини-графиков.

### Альтернативный вариант: @ant-design/charts

Если важна максимальная визуальная согласованность с Ant Design, можно рассмотреть `@ant-design/charts` — обёртку над движком G2 от Ant Group. Плюсы: единый дизайн-язык. Минусы: меньше сообщество, больше бандл, документация преимущественно на китайском.

## 5. Цветовая палитра и темизация

### Основной принцип

Для операционного дашборда компании по доставке воды рекомендуется **профессиональная сине-голубая палитра** с нейтральным фоном. Синий цвет ассоциируется с надёжностью, стабильностью и профессионализмом — критически важно для финансового и складского интерфейса.

### Рекомендуемая цветовая схема

#### Основные цвета (Light Mode)

| Элемент                | Цвет                   | Hex                   | Назначение                                                         |
| ---------------------- | ---------------------- | --------------------- | ------------------------------------------------------------------ |
| **Primary**            | Синий                  | `#1677FF`             | Ant Design primary по умолчанию. Кнопки, ссылки, активные элементы |
| **Page Background**    | Светло-серый           | `#F5F7FA`             | Фон страницы                                                       |

| **Sidebar Background** | Тёмно-синий/графитовый | `#001529`             | Ant Design sider по умолчанию                                      |

### Dark Mode (опционально)

Для операционного дашборда, используемого в офисных условиях (днём, при хорошем освещении), **основной режим — Light Mode**. Однако рекомендуется предусмотреть переключение на Dark Mode:

| Элемент         | Hex       |
| --------------- | --------- |
| Page Background | `#141414` |
| Card Surface    | `#1F1F1F` |
| Sidebar         | `#000000` |
| Primary Text    | `#E8E8E8` |
| Secondary Text  | `#8C8C8C` |
| Border          | `#303030` |

Ant Design v6 поддерживает Dark Mode через `ConfigProvider` с `algorithm: theme.darkAlgorithm`.

**Рекомендация:** Реализовать Light Mode как основной. Dark Mode — как опциональный через переключатель в header. Учитывая, что 55% пользователей финансовых приложений предпочитают Light Mode, а пользователи MunavvarA работают преимущественно в офисе днём — Light Mode по умолчанию.

Ant Design Grid: `<Col xs={24} sm={12} lg={6}>` — автоматическая адаптация.

### Рекомендации по макету

1. **CSS Grid + Flexbox комбинация:** Grid для общей структуры страницы (2D-разметка), Flexbox для внутренней раскладки компонентов (1D-направление)
2. **minmax() для адаптивных колонок:** `grid-template-columns: repeat(auto-fit, minmax(280px, 1fr))` — карточки автоматически перестраиваются
3. **Фиксированный sidebar на десктопе:** Не скроллится вместе с контентом, всегда доступен
4. **Sticky header:** Всегда видимый при прокрутке, содержит breadcrumb и быстрые действия
5. **ProLayout** от Ant Design реализует всё вышеперечисленное из коробки

## 7. Типографика

### Рекомендуемые шрифты

**Основной шрифт: Inter**

- Оптимизирован для экранов, отличная читаемость при малых размерах
- Широкий диапазон начертаний (100-900)
- Tabular numbers (цифры одинаковой ширины) — критично для финансовых таблиц
- Бесплатный, Google Fonts
- Лидер среди UI-шрифтов в 2025-2026

**Альтернатива: Ant Design System Font Stack**

```css
font-family:
  -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue",
  Arial, "Noto Sans", sans-serif;
```

Ant Design использует системные шрифты по умолчанию, что обеспечивает максимальную производительность (нет загрузки шрифтов).

**Для цифр и финансовых данных: Inter с font-variant-numeric: tabular-nums**

- Все цифры занимают одинаковую ширину — колонки выровнены
- Ant Design Statistic компонент автоматически применяет tabular-nums

### Иерархия типографики

| Уровень                         | Размер  | Начертание     | Использование                            |
| ------------------------------- | ------- | -------------- | ---------------------------------------- |
| **H1 (заголовок страницы)**     | 24px    | SemiBold (600) | «Заказы», «Финансы», «Склады»            |
| **H2 (заголовок секции)**       | 20px    | SemiBold (600) | «Финансовый дашборд», «Список должников» |
| **H3 (заголовок карточки)**     | 16px    | Medium (500)   | Заголовок stat-карточки, таблицы         |
| **Body (основной текст)**       | 14px    | Regular (400)  | Текст в таблицах, формах, описаниях      |
| **Small (вспомогательный)**     | 12px    | Regular (400)  | Подписи, даты, ID, secondary info        |
| **KPI-число (главная метрика)** | 30-36px | SemiBold (600) | Сумма выручки, долгов, кассы             |
| **KPI-изменение**               | 14px    | Medium (500)   | «+12.5%» рядом с главной метрикой        |
| **Монетные суммы в таблице**    | 14px    | Medium (500)   | font-variant-numeric: tabular-nums       |

### Принципы типографической иерархии

1. **Не более 3 размеров шрифта** на одном экране — заголовок, тело, мелкий текст
2. **Не более 2 начертаний** на одном экране — Regular и SemiBold/Bold
3. **Контраст через размер, не через цвет** — крупные числа привлекают внимание без кричащих цветов
4. **Выравнивание сумм по правому краю** в таблицах — стандарт финансовых отчётов
5. **Однострочные метки** — если текст не помещается, усекать с `...` (tooltip при наведении)

## 9. Паттерны проектирования

### 9.1 Modal vs Drawer vs Inline Editing

| Действие                             | Паттерн                      | Обоснование                                   |
| ------------------------------------ | ---------------------------- | --------------------------------------------- |
| **Создание заказа**                  | Drawer (справа, 600px)       | Много полей, нужен контекст основной страницы |
| **Создание клиента «Единое окно»**   | StepsForm в Drawer           | 4 шага, сложная форма, атомарная операция     |
| **Редактирование товара**            | Modal (520px)                | Простая форма, 5-7 полей                      |
| **Подтверждение/отклонение платежа** | Popconfirm / Modal           | Быстрое действие, требует подтверждения       |
| **Назначение курьера**               | Modal с Select               | Выбор из списка, быстрое действие             |
| **Детали заказа**                    | Drawer (справа, 720px)       | Много информации, нужен контекст списка       |
| **Редактирование позиции заказа**    | Inline editing в таблице     | Быстрое изменение количества                  |
| **Удаление/архивация**               | Popconfirm                   | Подтверждение деструктивного действия         |
| **Закрытие смены**                   | Полноэкранная страница       | Сложный 4-шаговый процесс, требует фокуса     |
| **Создание перемещения**             | Drawer с динамической формой | Разные поля для разных типов перемещений      |

### 9.2 Состояния компонентов

**Загрузка (Loading):**

- Скелетоны (Ant Design `Skeleton`) вместо спиннеров для карточек и таблиц
- Спиннер (`Spin`) для действий в кнопках
- Skeleton.Input, Skeleton.Button для форм
- Индикатор загрузки в header при навигации между страницами

**Пустое состояние (Empty State):**

- Ant Design `Empty` компонент с иллюстрацией
- Контекстное сообщение: «Нет заказов за выбранный период» (не просто «Нет данных»)
- Call-to-action кнопка: «Создать первый заказ»
- Разные иллюстрации для разных разделов

**Ошибка (Error State):**

- `Result` компонент для полноэкранных ошибок (404, 500, 403)
- `Alert` для секционных ошибок (не удалось загрузить блок)
- Toast-уведомления (`message` / `notification`) для ошибок действий
- Контекстные сообщения: «Не удалось загрузить дашборд. Проверьте подключение и попробуйте снова»

### 9.3 Уведомления и алерты

| Тип                           | Компонент Ant Design            | Когда использовать                                   |
| ----------------------------- | ------------------------------- | ---------------------------------------------------- |
| **Мгновенная обратная связь** | `message.success/error/warning` | После действия (создан заказ, ошибка сохранения)     |
| **Информативное уведомление** | `notification.open`             | Новый заказ от клиента, платёж ожидает подтверждения |
| **Постоянное предупреждение** | `Alert` (inline)                | Расхождения при инвентаризации, блокирующие условия  |
| **Подтверждение действия**    | `Modal.confirm` / `Popconfirm`  | Отмена заказа, удаление товара, отклонение платежа   |

**Автозакрытие:**

- `message` — 3 секунды
- `notification` — 5 секунд (или manual dismiss для важных)
- `Alert` — не закрывается автоматически (closable вручную или нет)

**Позиционирование:**

- `message` — top center
- `notification` — top right (десктоп)

### 9.4 Таблицы данных — лучшие практики

**Серверная пагинация, сортировка, фильтрация:**

- RTK Query endpoint с параметрами `page`, `page_size`, `sort`, `filters`
- ProTable `request` API автоматически управляет параметрами
- При изменении фильтров/сортировки — автоматический сброс на первую страницу
- Сохранение состояния фильтров в URL (query params) для bookmark/share

**Размер страницы:** 20 строк по умолчанию, опции: 10, 20, 50, 100

**Фиксация элементов:**

- Sticky header таблицы при прокрутке
- Fixed первая колонка (ID/Имя) и последняя (Действия) при горизонтальной прокрутке
- Summary row (итого) зафиксирована внизу таблицы

**Inline-действия:**

- Иконки без текста для экономии места: ✏️ Редактировать, 👁 Просмотр, 🗑 Удалить
- При наведении — tooltip с описанием
- Dropdown `...` для дополнительных действий
- Максимум 3 видимые иконки + dropdown

### 9.5 Отображение финансовых сумм

**Формат валюты (UZS — узбекский сум):**

```
Целые числа:       1 234 567 сум     (пробел как разделитель тысяч)
С тийинами:        1 234 567,89 сум  (запятая как десятичный разделитель)
```

Учитывая, что в системе цены хранятся в тийинах (минимальных единицах), на UI нужно:

- Делить на 100 для отображения
- Форматировать с пробелами-разделителями тысяч
- Использовать запятую как десятичный разделитель (Узбекистан)
- Добавлять «сум» или «UZS» после числа

**Цветовая кодировка:**

- Положительные суммы (приход): зелёный `#52C41A`
- Отрицательные суммы (расход): красный `#FF4D4F`
- Долг клиента: красный (это деньги, которые должны компании)
- Выручка на дашборде: показывать с обратным знаком (по бизнес-логике баланс выручки отрицательный, но на UI показываем как положительную метрику)

**Формат в скобках для отрицательных:**
В финансовых таблицах (выписки) рекомендуется формат со скобками:

```
  50 000 сум     — приход (зелёный)
 (20 000 сум)    — расход (красный, в скобках)
```

Этот формат соответствует бухгалтерским стандартам (GAAP) и сразу понятен бухгалтеру.

```typescript
// utils/formatCurrency.ts

/**
 * Форматирует сумму из тийинов в читаемый формат UZS.
 * Вход: 12345600 (тийины)
 * Выход: "123 456 сум" или "123 456,00 сум"
 */
export function formatMoney(
  amountInTiyin: number,
  options?: { showTiyin?: boolean; showCurrency?: boolean },
): string {
  const { showTiyin = false, showCurrency = true } = options ?? {};
  const amount = amountInTiyin / 100;

  const formatted = new Intl.NumberFormat("uz-UZ", {
    minimumFractionDigits: showTiyin ? 2 : 0,
    maximumFractionDigits: showTiyin ? 2 : 0,
  }).format(Math.abs(amount));

  const sign = amountInTiyin < 0 ? "-" : "";
  const currency = showCurrency ? " сум" : "";

  return `${sign}${formatted}${currency}`;
}

/**
 * Бухгалтерский формат (скобки для отрицательных).
 */
export function formatMoneyAccounting(amountInTiyin: number): string {
  const abs = formatMoney(Math.abs(amountInTiyin), { showCurrency: true });
  return amountInTiyin < 0 ? `(${abs})` : abs;
}
```

## 13. Практические рекомендации

### Приоритетный план внедрения

**Фаза 1 — Фундамент (неделя 1-2):**

1. Установить Ant Design v6, ProComponents, Recharts
2. Настроить тему (цвета, шрифты, отступы) через ConfigProvider
3. Создать AppLayout с ProLayout (sidebar + header)
4. Настроить маршрутизацию (React Router v7) с конфигурацией меню по ролям
5. Создать базовые обёртки: CrudTable, DrawerForm, ModalForm, StatCard

**Фаза 2 — Критические страницы (неделя 3-5):**

1. Финансовый дашборд (KPI-карточки + графики выручки)
2. Управление заказами (таблица + создание + детали)
3. Управление клиентами (таблица + создание «Единое окно» + карточка)
4. Авторизация (LoginForm)

**Фаза 3 — Операционные страницы (неделя 6-8):**

1. Управление курьерами + транспорт
2. Склады + остатки
3. Журнал перемещений + создание перемещения
4. Каталог товаров

**Фаза 4 — Финансовые инструменты (неделя 9-10):**

1. Подтверждение карточных платежей
2. Выписка по счёту
3. Отчёт по должникам
4. Сводка по курьерам
5. Касса (приём платежей)

**Фаза 5 — Процессы (неделя 11-12):**

1. Закрытие смены курьера (StepsForm)
2. Инвентаризация
3. Уведомления (ожидающие платежи, новые заказы)
4. Экспорт в PDF

### Технические рекомендации

1. **RTK Query как единый слой данных:**
   - Один API slice на `baseApi.js` (уже в проекте)
   - Tag-based invalidation для автоматического обновления (например, после подтверждения платежа обновляются балансы)
   - Оптимистичные обновления для быстрых действий (смена статуса)

2. **URL-синхронизация состояния таблиц:**
   - Фильтры, сортировка, пагинация — в URL query params
   - Пользователь может поделиться ссылкой на отфильтрованный список
   - При обновлении страницы — состояние восстанавливается

3. **RBAC на фронтенде:**
   - Сайдбар фильтрует пункты меню по scopes пользователя
   - Кнопки действий скрыты при отсутствии прав
   - `useRoleAccess` хук для условного рендеринга

4. **Интернационализация (i18n):**
   - Ant Design имеет встроенную поддержку ru_RU и uz_UZ локалей
   - ConfigProvider с `locale={ruRU}` для русскоязычного интерфейса
   - Формат дат: `DD.MM.YYYY` (российский стандарт)
   - Формат чисел: пробел как разделитель тысяч, запятая для десятичных

5. **Печать отчётов:**
   - CSS `@media print` для оптимизации таблиц при печати
   - `react-to-print` для мгновенной печати выписок и отчётов
   - `@react-pdf/renderer` для генерации PDF-документов (акты, счета)
   - Скрытие сайдбара, header, кнопок действий при печати

6. **Производительность:**
   - Виртуализация длинных списков (`react-window` или встроенная в ProTable)
   - Lazy loading страниц через React.lazy + Suspense
   - Skeleton-loading вместо полноэкранных спиннеров
   - Debounce на поисковых полях (300ms)

### Ключевые решения, от которых не следует отступать

1. **Ant Design v6 + ProComponents** — не менять на MUI/Mantine в середине проекта
2. **Recharts** для графиков — не тянуть ECharts (800KB) или несколько библиотек
3. **Light Mode по умолчанию** — операционный дашборд в офисе = светлая тема
4. **Серверная пагинация везде** — никогда не загружать все записи на клиент
5. **ProTable как основная таблица** — не писать кастомные таблицы
6. **Drawer для создания/деталей** — не перенаправлять на отдельные страницы для каждой сущности
7. **URL-синхронизация фильтров** — для каждой таблицы
